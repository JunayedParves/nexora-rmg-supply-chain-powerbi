# The Storytelling Engine: Dynamic Action Titles with DAX User-Defined Functions

Knaflic's rule is that a chart title should state the takeaway. In a static slide that is easy. In an interactive dashboard, a hard-coded title like *"Revenue grew 4.0x"* becomes a lie the moment someone filters to a single company. The fix is to make the **sentence itself a measure**.

Writing ~130 such measures by hand would be unmaintainable, so the logic lives in **8 DAX user-defined functions** (`definition/functions.tmdl`), and every storytelling measure is a one-line call.

| Function | Produces | Example output |
|---|---|---|
| `Nexora.Fmt(v, kind)` | Compact number text (`usd`, `cnt`, `pct1`, `days`, …) | `$939M`, `112.4M`, `39.6%` |
| `Nexora.TrendTitle(m, label, fmt, up, down, ratio)` | First-vs-last-year trend sentence | *Shipped revenue grew from $236M in 2006 to $939M in 2025 (4.0x)* |
| `Nexora.RankTitle(column, m, fmt, lowFirst, n, pattern)` | Top/bottom-n sentence with `{name} {value} {share} {total}` | *Two buyers (Metro British UNI Ltd. and Vanguard Eco GER Ltd.) generate 41% of revenue* |
| `Nexora.TwoRatio(mA, mB, pattern)` | Compares two growth multiples | *Since 2006, the minimum wage rose 7.5x while output per labour hour rose only 1.1x* |
| `Nexora.KpiContext(m, fmt, kind)` | KPI context line (vs first year, or vs prior year when one year is selected) | *2025: 39.6%   ▼ 23.1 pts vs 2006* |
| `Nexora.KpiColor(context, good)` | Orange only when the KPI moved the wrong way | `#B54708` / `#4B5563` |
| `Nexora.BarColor(column, m, lowFirst, n, colour)` | Highlight colour for the top/bottom-n bars, grey for the rest | navy for China, grey for others |
| `Nexora.Index(m)` | Index a series to 100 in the first selected year | lets BDT wages and pieces/hour share one axis |

## Example

```dax
// the measure behind the Quality page's first chart title
Title | p7_vis01 =
Nexora.RankTitle (
    dim_company[company_name],
    [AQL Defect Rate %],
    "pct1",
    0,   // highest first
    1,   // top 1
    "{name} has the highest defect rate at {value} vs {total} for the group"
)
// → "Surma Jacquard & Sweaters Ltd. has the highest defect rate at 4.9% vs 3.7% for the group"

// the matching bar colour, bound to the chart's data colour (field value)
Color | p7_vis01 = Nexora.BarColor ( dim_company[company_name], [AQL Defect Rate %], 0, 1, "#B54708" )
```

```dax
// inside Nexora.KpiContext: compare latest vs first selected year,
// or vs the prior year when only one year is selected
VAR _Yrs = FILTER ( VALUES ( dim_date[calendar_year] ), NOT ISBLANK ( m ) )
VAR _Y1  = MAXX ( _Yrs, dim_date[calendar_year] )
VAR _Y0a = MINX ( _Yrs, dim_date[calendar_year] )
VAR _Y0  = IF ( _Y0a = _Y1, _Y1 - 1, _Y0a )
VAR _D1  = CALCULATE ( m, dim_date[calendar_year] = _Y1 )   // m is an EXPR parameter,
VAR _D0  = CALCULATE ( m, dim_date[calendar_year] = _Y0 )   // re-evaluated under each filter
```

Measure parameters are declared `SCALAR NUMERIC EXPR` and column parameters `ANYREF EXPR`, so the function re-evaluates the caller's measure under its own filters, exactly like inlined DAX.

## Wiring it to visuals (PBIR)

Titles, KPI subtitles and bar colours bind to measures instead of literals:

```json
"title": [{ "properties": {
  "text": { "expr": { "Measure": { "Expression": { "SourceRef": { "Entity": "Executive_Measures" } }, "Property": "Title | p1_vis01" } } }
} }]
```

```json
"dataPoint": [{
  "properties": { "fill": { "solid": { "color": { "expr": { "Measure": { "…": "Color | p3_vis01" } } } } } },
  "selector": { "data": [{ "dataViewWildcard": { "matchingOption": 1 } }] }
}]
```

The measure catalogue is generated by [`tools/storytelling_measures.js`](../tools/storytelling_measures.js), and the visuals by [`tools/build_storytelling.js`](../tools/build_storytelling.js). To change a story, edit one line and regenerate.

## Lessons learned

- `asc` is a reserved word and cannot be a function parameter name. `Trend` caused a parse clash as a function name, so it is `TrendTitle`.
- User-defined functions need model **compatibility level 1702**.
- Measures and functions created against a *running* Power BI Desktop through external tools were not persisted by Desktop's save. Adding them to the TMDL with Desktop closed is reliable.
